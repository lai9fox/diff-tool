# 文本差异对比网站需求说明

版本：v1.0  
日期：2026-09-29  
范围：首版（MVP）  
技术选型：Astro + Vue

## 1. 产品定位

面向电脑浏览器的文本差异对比工具，主要用于比较较长代码和配置文件，同时兼顾中文长文案。用户可以快速输入两段文本、定位改动，并在对比过程中进行少量编辑，最终复制需要的文本。

核心使用流程：

> 粘贴文本或打开本地文件 → 查看差异 → 少量编辑 → 复制完整文本

产品优先保证差异清晰、长文本操作流畅和使用步骤简单。文本在浏览器本地处理，不依赖正文上传或服务端存储。

## 2. 目标用户与使用场景

首版主要服务需要临时比较文本的个人用户，优先优化电脑操作体验。

| 场景       | 用户任务                   | 预期结果                           |
| ---------- | -------------------------- | ---------------------------------- |
| 代码对比   | 比较两段几百至几千行的代码 | 快速定位新增、删除和行内修改       |
| 配置对比   | 比较两个配置版本           | 看清配置项变化，按需忽略行首尾空白 |
| JSON 对比  | 比较两份 JSON 文本         | 直接按输入文本显示差异             |
| 长文案对比 | 比较两版中文长文案         | 看清段落中的具体字句修改           |
| 对比中修改 | 在任一侧修正少量内容       | 自动刷新差异，复制调整后的完整文本 |

### 3.2 首版不包含

- 按差异块接受修改、左右合并或三方合并。
- JSON 格式化、按键排序、忽略字段顺序或按数据结构进行语义比较。
- 正文历史记录、自动草稿恢复、云端保存或分享链接。
- 文件夹、批量文件、PDF、Word 或其他富文档对比。
- 专门为手机设计的完整编辑流程。

以上能力不作为首版验收要求，也不预留专门的实现工作。

## 4. 页面与交互要求

### 4.1 页面结构

页面以对比工作区为主体，包含以下区域：

1. **工具区**：布局切换、自动折行、忽略行首尾空白、展开或折叠相同内容、清空全部或撤销清空。
2. **两侧输入操作区（仅左右编辑模式）**：明确区分“原文”和“修改后”，分别提供文件选择和复制入口；非空时在各自标题旁显示行数。
3. **对比区**：展示可编辑双栏或只读合并视图。
4. **工作区工具栏右侧状态区**：显示比较状态、差异块数量和差异导航。页面底部不设置说明或统计栏。

已确认产品名称为 Diff，界面支持简体中文和英文、浅色和暗色主题，默认中文、浅色。语言文字或主题图标显示当前状态，右侧开关一键切换并记住选择，不提供跟随系统选项。所有工具展开显示。首次进入两侧为空，不提供示例入口。

空白引导为“粘贴原文 / 粘贴修改后文本”，下方仅显示“或拖入文件”。清空全部直接执行，无确认弹窗，保留布局、主题、语言及比较选项。

具体排版、视觉样式与交互状态见 [UI / UX 设计说明](./ui-ux-design.md)，本说明不限定组件库和编辑器库。

### 4.2 输入与编辑

- 左侧表示原文，右侧表示修改后文本；两侧都允许编辑。
- 粘贴或导入后自动进行对比，无须点击“开始比较”。
- 文件导入到用户指定的一侧，并替换该侧内容，不改变另一侧。
- 拖入文件时，能够辨认文件将进入哪一侧。
- 本地文件作为文本读取；读取或解码失败时给出可理解的提示，并保留已有内容。
- 连续输入时适当延后差异计算，在用户短暂停止输入后更新，避免影响输入流畅度。
- 对比更新不应打断输入、抢走焦点或无故移动光标。
- 切换显示方式后，两侧当前文本保持不变。

### 4.3 差异展示

- 新增与删除使用可区分的颜色，并配合 `+`、`−` 等标识，避免仅靠颜色表达。
- 修改行除了行级标记，还应突出行内具体变化的字符。
- 中文文案需要支持字符级变化标记，不能只将整段标成变化。
- 纯文本保留行级和行内差异标记。
- 行号对应原始文本的实际行；自动折行不新增逻辑行号。
- 对齐所需的占位行仅用于展示，不写入原文或复制结果。

### 4.4 两种对比视图

**左右视图（默认）**

- 两侧并排，支持编辑、行号和对应内容对齐。
- 滚动时保持对应内容同步，便于比较同一位置。
- 一侧存在新增或删除行时，通过显示占位维持可理解的对应关系。

**合并视图**

- 使用一个合并后的差异视图；删除行和新增行相邻排列。
- 此视图只用于阅读，不提供直接编辑。标题行统一显示“合并对比”和“只读”，右侧提供“返回编辑”；打开文件及复制操作位于左右编辑模式。
- 需要修改时，用户切回左右视图继续操作。
- 不采用上、下两个独立编辑器的布局。

### 4.5 差异导航与相同内容折叠

- 差异数量按“差异块”统计，不与新增行数、删除行数或修改字符数混用。
- 一个差异块指一段连续的新增、删除或修改区域。导航与数量使用同一划分规则。
- 提供上一处、下一处差异跳转，并显示当前位置，例如“第 2 / 8 处”。
- 跳转后使目标差异进入可见区域。
- 默认折叠连续相同内容，每处差异前后保留 3 行上下文；上下文重叠时合并展示。
- 支持展开某一段相同内容、展开全部，以及恢复折叠。
- 没有差异时明确显示一致状态，并使差异导航不可用。

### 4.6 自动折行

- 默认开启，左右视图和合并视图均可使用。
- 关闭后允许横向滚动查看长行。
- 开关只改变显示，不插入或删除换行符，不改变差异计算结果。
- 左右视图中折行后的对应内容仍应保持可读的对齐关系。

## 5. 比较规则与 JSON 处理

### 5.1 默认比较规则

- 按文本内容进行比较，保留大小写、标点、空白及字段顺序的差异。
- 默认将 Windows 的 CRLF 与 Unix 的 LF 视为等价换行形式。
- 忽略换行形式不等于忽略空行，也不修改编辑区中的正文。
- 提供“忽略行首尾空白”开关，默认关闭。
- 开启后，仅在比较时忽略每行首尾的空格、制表符等空白；行内空白仍参与比较。
- 忽略规则不删除、格式化或覆盖用户输入。

### 5.2 一致状态

- 默认规则下无差异时，显示“内容一致”。
- 开启“忽略行首尾空白”后无差异时，显示“当前比较规则下无差异”，并保持该选项状态可见。
- 一致状态始终基于当前规则，不暗示原始文件的字节完全一致。

### 5.3 JSON 文本比较

- JSON 与其他文本使用相同的比较规则，直接比较输入内容，不提供格式化操作。
- JSON 按纯文本处理，不识别类型或添加语法着色；字段顺序不同仍显示为文本差异。
- JSON 语法无效不阻止文本比较，也不触发 JSON 解析错误提示。
- 不自动按键排序，不将 JSON 语义一致视为文本一致。

## 6. 文本复制、隐私与状态保存

- 分别提供复制左侧、复制右侧完整文本的操作，并显示成功或失败反馈。
- 复制内容为该侧当前完整正文，不包含行号、差异符号、折叠提示或显示占位。
- 折叠、折行、切换视图或开启忽略规则，不改变复制内容。
- 对比和文件读取均在浏览器本地完成。
- 不将正文发送到服务器、分析服务或错误日志服务。
- 不主动将正文写入本地持久存储；刷新或关闭页面后不提供自动恢复。
- 可记住布局、自动折行等显示设置，不将正文作为设置保存。

## 7. 性能与兼容要求

- 优先优化电脑浏览器的输入、编辑、滚动和差异定位体验。
- 目标规模为几千行代码或几万字中文文案。
- 该规模下应能持续操作页面，避免差异计算导致明显的输入阻塞或长时间无响应。
- 对比尚未完成时显示正在计算的状态，不能将未完成的结果显示为“内容一致”。
- 处理失败时提供明确反馈，保留当前输入，允许用户修改内容后重试。
- 小屏幕以基本查看和操作入口可达为目标，完整手机编辑体验不作为首版验收条件。
- 性能验收使用固定参考电脑、浏览器和样本记录结果；本阶段不承诺尚未实测的毫秒级指标或最大文件容量。

## 8. 验收标准

| 编号 | 验收场景                           | 通过条件                                                                               |
| ---- | ---------------------------------- | -------------------------------------------------------------------------------------- |
| A01  | 两侧输入完全相同的文本             | 显示“内容一致”，差异导航不可用                                                         |
| A02  | 一侧新增、删除或修改若干行         | 能区分变化类型，并标出修改行内的具体变化                                               |
| A03  | 中文长段落中只改几个字             | 能直接识别变化字符，无须人工逐字检查整段                                               |
| A04  | 左右任一侧进行少量编辑             | 停止输入后差异与数量自动更新，光标和焦点正常，撤销可用                                 |
| A05  | 在左右视图和合并视图之间切换       | 内容不丢失；合并视图只读；切回左右后可继续编辑                                         |
| A06  | 长文本中有多处不连续变化           | 数量与导航一致，上一处、下一处能定位对应差异                                           |
| A07  | 默认折叠、局部展开、全部展开       | 差异与上下文清晰，展开操作不改变正文                                                   |
| A08  | 同一长行切换自动折行               | 只改变显示方式，差异结果与复制内容不变                                                 |
| A09  | 仅行首尾空白不同                   | 默认显示差异；开启忽略选项后显示当前规则下无差异                                       |
| A10  | 仅 CRLF 与 LF 不同                 | 默认不显示差异；额外空行仍能被识别                                                     |
| A11  | 两侧导入本地文本文件               | 内容进入对应侧并自动比较；读取失败时保留原有内容                                       |
| A14  | JSON 内容相同但字段顺序不同        | 直接显示顺序造成的文本差异，不改写正文                                                 |
| A15  | 在左右视图中（含折叠时）复制任一侧 | 获得该侧完整正文，不包含展示辅助内容                                                   |
| A16  | 使用几千行代码和几万字文案         | 输入、滚动、编辑及差异导航可连续操作，无长时间卡死                                     |
| A17  | 检查网络请求与本地存储             | 正文未被上传或主动持久保存；刷新后不自动恢复正文                                       |
| A18  | 清空与撤销清空                     | 两侧正文、文件名一起清除；撤销可同时恢复，设置保持不变；输入或导入新内容后撤销入口消失 |

## 9. 技术边界与后续实施

- 使用 Astro 承载页面，使用 Vue 实现交互式对比工作区。
- 首版采用浏览器本地文本处理，不需要正文处理后端。
- 编辑器、差异计算库及性能实现方式在开发阶段确定，以满足本说明为准。
- 实现优先验证长文本的双侧编辑、差异展示和滚动体验，再补齐其余操作。
- 本文是需求说明，不代表相关功能已经实现或完成性能验证。
